# codeguide-landing-pro App Flow Document

## Onboarding and Sign-In/Sign-Up
A visitor begins their journey by navigating to the codeguide.dev landing page. The landing page presents a clear call to action inviting the user to get started or join the waitlist. When the user clicks "Get Started," they are taken to a dedicated sign-up screen provided by Clerk. This screen lets the user sign up with an email and password or choose a social login option such as Google or GitHub. If the user opts to use their email, the form asks for their email address, a password, and a brief acceptance of the terms of service. Once the user submits the information, Clerk sends a confirmation email. After the user verifies their email, they are automatically signed in and redirected to the main application.

If a returning user arrives, they can click on the "Sign In" link in the header, which opens Clerk’s sign-in dialog. Forgotten passwords are handled by a "Forgot your password?" link; clicking it prompts the user to enter their email address, then Clerk sends a password reset email. After successfully resetting the password, the user is redirected back to the sign-in screen to log in with their new credentials. Throughout this process, the user always has access to a "Back to Landing Page" option and can easily sign out by selecting their avatar in the top-right corner and clicking "Sign Out."  

## Main Dashboard or Home Page
Upon successful login, the user lands on the main Dashboard. The layout features a persistent header at the top containing the codeguide.dev logo on the left and the user’s avatar on the right. A collapsible sidebar on the left lists navigation links for Dashboard, Courses, AI Assistant, Billing, and Settings. In the center of the Dashboard, the user sees an overview of their current status: subscription tier, recent activity, and any unread notifications. A real-time notification bell updates instantly when new messages or alerts arrive thanks to Supabase’s real-time features. The default view is the Dashboard summary, but the user can click any sidebar link to navigate to other parts of the app.

## Detailed Feature Flows and Page Transitions
When the user selects the Courses link, the app fetches a list of available courses using TanStack React Query. A loading spinner appears until the data arrives. Once loaded, each course is rendered as a card. Clicking on a course card transitions the user to a course detail page where lessons are listed. Starting a lesson opens a lesson viewer that can stream video or display text content, with progress automatically saved in Supabase.

If the user chooses the AI Assistant link, they are taken to a chat interface. The user types a question or code snippet into the input field. Upon submission, the app sends a request to the OpenAI API via a secured server action. While awaiting the response, a typing indicator appears. When the AI response arrives, it is appended to the chat window and stored in Supabase for future reference.

Accessing the Billing page shows the user’s current subscription plan, renewal date, and next payment amount. A button labeled "Change Plan" triggers a Stripe checkout session through a secured Next.js API route. The user is redirected to Stripe’s hosted checkout, completes payment, and is sent back to the Billing page. Meanwhile, Stripe issues a webhook that the app handles in the `app/api/webhooks/route.ts` endpoint. This endpoint verifies the event and updates the user’s subscription record in Supabase. The UI then reflects the new plan instantly.

Admin users, identified by a role flag in their profile, see an additional Admin Panel link in the sidebar. This panel allows them to create or edit courses, manage users, and view analytics. Navigating between pages always preserves the sidebar and header, ensuring a consistent user experience.

## Settings and Account Management
Clicking the Settings link brings the user to their Account Settings page. Here they can edit personal details such as name, email, and profile photo. Changing the email triggers a re-verification process via Clerk. Below profile details, users find Notification Preferences where they can toggle email or in-app alerts. A separate Billing Settings section lists saved payment methods—users can add or remove cards powered by Stripe. There is also a subscription management area where users can cancel or restart their plan. After making changes, a "Save Changes" button writes updates to both Clerk and Supabase as needed. A link at the top of Settings allows the user to return directly to the Dashboard.

## Error States and Alternate Paths
If a user submits invalid credentials during sign-in, Clerk displays a clear error message below the form. During sign-up, using an already-registered email triggers a duplicate account warning. When loading data fails—such as retrieving courses or user profile information—the UI shows a friendly message indicating that something went wrong and offers a retry button. If network connectivity is lost, a banner appears at the top of the screen prompting the user to check their connection. In the Billing flow, if the Stripe checkout fails or is canceled, the user is redirected back to the Billing page with an error notification explaining the issue and suggesting next steps. Attempting to navigate to the Admin Panel without proper permissions leads to a 403-style page stating the user is not authorized, with a button to return to the Dashboard.

## Conclusion and Overall App Journey
The user’s journey begins at the public landing page, where they can either join a waitlist or sign up for immediate access. After account creation and email verification, they arrive at the Dashboard with a clear overview of their subscription status and recent activity. From there, they can explore courses, chat with the AI Assistant, and manage their subscription in the Billing area. Settings allow them to keep personal details and notifications up to date, while error states guide them through any issues. Admin users have an extra pathway to manage content and users. In all cases, the sidebar and header remain constant, ensuring smooth navigation. The user can sign out at any time, completing a seamless loop from discovery to regular engagement with the codeguide-landing-pro application.
